## D-001：重新打开 M1

状态：已接受

旧 `voyage / breath / signal` 原型的基础设施验证有效，但人工视觉验收失败。M1 必须重新打开，不能因构建或静态审计通过而标记完成。

## D-002：旧候选只保留历史

状态：已接受

旧候选保留在 Git 历史和验收材料中，不删除、不继续作为产品候选，也不作为新视觉的截图基准。

## D-003：背景使用展示坐标空间

状态：已接受

理论坐标继续提供身份、热点归属和语义关系，但 Agent 背景允许使用版本化流场重新表达位置。展示变换不得反向修改理论星图或声称自己是严格理论坐标。

## D-004：流动形态暂不固定

状态：已接受

先建立可替换 `FlowModel`。引力织场用于第一轮技术验证，潮汐/Curl 流保留为后续适配器；两者都不预设为产品候选，最终形态必须依据动态视频人工选择。

## D-005：清晰度优先于粒子数量

状态：已接受

语义星必须拥有全分辨率锐利亮核，不参与景深模糊、运动模糊和低分辨率放大。性能不足时先减少装饰粒子和后处理。

## D-006：颜色克制

状态：已接受

默认颜色以银白、冷灰和低饱和灰蓝为主。热点通过尺寸、密度和局部关系表达，只有当前焦点允许短暂增加能量或饱和度。

## D-007：3,840 是常驻预算，不是检索边界

状态：已接受

背景只常驻 3,840 个确定性抽样论文代理。库中其他论文通过只读解析和动态焦点层按需出现。

## D-008：区分快照内未抽样与新信号

状态：已接受

背景快照内未抽样论文直接在所属流带凝聚；只存在于活动数据库或更新快照的论文标记为“新信号”；不存在实体不伪造位置。

## D-009：呼吸不改变语义星核心透明度

状态：已接受

呼吸使用局部密度、空间潮汐和弱光晕变化。语义星中央亮核不得通过时间驱动透明度闪烁。

## D-010：默认首页延后

状态：已接受

参数化引擎、动态聚焦、性能和人工视觉选择完成前，不替换默认首页、不改造对话框和侧栏。

## D-011：引力织场只作为第一套技术骨架

状态：已接受

M1.2a 先实现 `gravitational-weave-tech-preview`，验证固定相机下由知识空间自身产生的拉伸、压缩、剪切、弯曲与恢复。技术审计通过不能把它自动升级为最终主视觉；动态视频人工验收仍是停止门。

## D-012：固定相机作为运动真实性基准

状态：已接受

M1.2a 的主要视觉验收使用固定相机，排除相机环绕、整景旋转和统一平移制造的伪流动。轻微协同漂移只作为补充视差，位移不得超过 `0.6` 世界单位，周期不得短于 60 秒。

## D-013：中央对话区采用缓流而非留空

状态：已接受

未来对话框区域使用固定世界空间缓流椭球，将位移和速度降低约 30%。它不清空中央星体、不形成明显圆洞，也不跟随相机实时移动。

## D-014：M1.2a 保持黑白且无后处理

状态：已接受

第一轮只用银白、冷灰和石墨灰验证运动骨架；语义星采用正常透明混合，不加入 Bloom、景深、运动模糊、拖影或时间透明度。颜色和相位呼吸只有在运动语言被人工接受后才进入下一阶段。

## D-015：引力织场运动语言通过人工判断

状态：已接受

用户确认固定相机与轻微协同漂移的运动效果可以继续使用。视频中的星体轻微软化按录屏压缩处理，不允许因此在渲染器中加入模糊或降低锐利星核分辨率。

## D-016：论文聚焦使用三级触发

状态：已接受

普通提及触发 `signal`，Agent 重点论述触发 `soft-focus`，引用点击或明确聚焦触发 `full-focus`。完整聚焦持续到显式退出或目标切换；柔焦在回答结束约 2 秒后释放。

## D-017：完整聚焦采用中度接近与自适应避让

状态：已接受

完整聚焦约 2 秒进入共速视角，与目标保持约 44 世界单位距离。目标根据原投影侧进入最近安全区域，避开未来居中对话框，不依赖改变 FOV 或移动目标世界坐标。

## D-018：星空不显示论文标题

状态：已接受

聚焦只使用同一论文星的尺寸、亮度、局部关系和相机变化表达。标题与引用信息由未来对话框承担，星空中不生成标签、圆环、准星或霓虹提示。

## D-019：常驻论文使用同一顶点聚焦

状态：已接受

M1.3a 保留全部 3,840 个稳定论文顶点。质量预算隐藏的常驻论文按 ID 提升原顶点，不创建替代对象；目标切换使用双槽交叉过渡，不要求旧目标先返回基础视角。

## D-020：评审背景采用纯黑，焦点采用低饱和语义材质

状态：已接受

引力织场评审背景统一使用 `#000000`。星体必须以紧致亮核和像素级边缘抗锯齿保持清晰，远处只能更小、更暗，不能更模糊。聚焦目标从所属热点颜色确定性派生低饱和材质，并通过连续的尺寸、RGB 能量和局部邻域关系表达；不加入 Bloom、圆环、准星、标题或时间透明度闪烁。具体光学实现由 D-021 的恒星光球 LOD 取代旧晶面方案。

## D-021：语义星统一采用恒星光球 LOD

状态：部分被 D-035 取代（SUPERSEDED）

论文星、热点星和聚焦论文曾统一使用“锐利核心 + 表面/薄层日冕”光球。M1.3e 保留飞近后的局部光球，但取消 Agent 理论概览热点的完整球面：概览改为混合恒星 LOD，避免方向光圆片产生行星感。

## D-022：语义色继承热点色相

状态：已接受

热点使用现有热点色的低饱和版本，论文继承同一色相但降低色度，聚焦只连续提高受光层次而不切换色相。年份、排名和数量不生成新色相；颜色只承担辅助语义，不替代尺寸、光球厚度、亮核比例和日冕层级。

## D-023：聚焦先可见，再响应空间，最后移动相机

状态：已接受

完整聚焦的顺序固定为 `FocusTimeline → FocusField → PhotosphereLOD → Camera`：前 0.65 秒完成目标捕获与光球展开，局部潮汐弯曲随后形成，相机约 0.95 秒后才开始接近。释放时相机先回归，目标与局部织场延迟衰减；即使关闭聚焦相机，完整聚焦也必须达到 `8.5 CSS px` 并可独立辨认。

## D-024：Agent 使用沉浸视图和理论视图双背景

状态：已接受

沉浸视图负责 Agent 对话、状态反馈和上下文抽取，理论视图负责论文语义位置、热点归属和可解释关系。两者共享实体身份、焦点意图、证据集合和快照身份，但使用独立空间解释器。

## D-025：外部原型作为沉浸视图保留式改造基线

状态：已接受

`D:\wenjian\Desktop\agent背景.html` 的纯黑背景、中央对话框、左右上下文构图和 `Idle / Thinking / Focus` 三态作为沉浸视图视觉参考。第一轮采用小幅调整，不进行视觉推翻；原型文件本身不作为生产依赖。

## D-026：视觉保留不等于复制随机运行时

状态：已废弃，由 D-030 取代

正式实现必须使用背景载荷、稳定实体身份、焦点意图和真实上下文集合，替换原型的随机位置、随机论文、欧氏半径邻域、固定点塌缩、全局强压暗和时间亮度噪声。用户可见构图保持接近，底层数据和生命周期按生产约束实现。

## D-027：普通对话不自动切换理论视图

状态：已接受

Agent 在沉浸视图中提及论文或热点时，先完成上下文抽取和证据展示。只有用户明确选择“查看语义位置”时才进入理论视图，避免在阅读回答时突然切换空间。

## D-028：聚焦以真实上下文抽取为主，相机仅辅助

状态：已接受

沉浸视图的主要聚焦表达由目标论文、真实证据和同热点语义邻域共同完成，不再依赖圆点膨胀或镜头推近。上下文最多 24 篇，保持原有顶点、身份和内部几何；目标尺寸上限约 `4.8 CSS px`，非上下文背景亮度下限为 `68%`。`signal` 不移动相机，`soft-focus` 和 `full-focus` 的接近幅度分别限制为约 `8%` 和 `15%`，且必须在上下文已经可辨认后启动。

上下文切换使用双槽交叉混合，证据顺序只控制连续显现进度，不重新排序、复制顶点或重建渲染器。

## D-029：背景实体来源必须明确且不可伪造

状态：已接受

实体解析统一区分 `sampled`、`snapshot-unsampled`、`active-only` 和 `missing`。常驻论文始终复用原顶点；快照内未抽样论文依据 V20 membership、热点坐标、`sourceCentroid` 和 `isotropicScale` 恢复精确背景坐标；活动库新增论文只能进入带版本的“未分类外围区”，不得携带伪造的热点归属或理论坐标；不存在的实体不生成星体、面板或占位关系。热点继续使用既有 160 个稳定身份。

## D-030：沉浸背景使用会话随机空间且禁止理论坐标

状态：已接受

真实身份不等于固定语义位置。沉浸背景忠实迁移 `agent背景.html` 的会话随机星海与 Curl 流：正常启动由 Web Crypto 生成会话种子，同一会话内连续、下次启动生成新星海。沉浸载荷只包含真实论文/热点身份、归属、颜色和必要年份，禁止包含或读取理论 XYZ、热点质心和论文语义偏移。固定种子只用于审计与截图。

## D-031：先完成双背景静置闭环

状态：已接受

M1.3d 只实现沉浸与理论两套基础背景、正式研究 Agent 页面、中央提交契约和显式切换。任意时刻只保留一个 WebGL 渲染器。聚焦、Thinking 波纹、六态动画和正式 Agent 后端在两套结构人工通过前不得继续叠加。

## D-032：理论背景保持真实结构但使用 Agent 专用视觉配置

状态：已接受

理论背景继续使用完整 V20 理论 XYZ、最佳视角和现有热点进入逻辑。Agent 页默认处于无标签、无拾取的 ambient 模式；显式进入 explore 后才开放拖拽、缩放、热点/论文点击和标签。Agent 专用锐利恒星材质不得改变独立理论星图或展示星图。

## D-033：沉浸背景采用状态化 GPGPU 两级流场

状态：已接受

M1.3e 使用 `128×64` 位置与速度纹理执行固定 `1/60s` 步长的 Ping-Pong 积分。大尺度输运负责可追踪迁移，小尺度 Curl 负责局部弯曲和层次；粒子不重生、不换位、不取模传送，也不通过整组平移或时间透明度伪造流动。

## D-034：沉浸流场必须提供解析式连续降级

状态：已接受

WebGL2、浮点渲染目标、framebuffer 或 context 不可用时，沉浸背景自动使用解析式两级流场。context lost 后本会话不再次尝试 GPGPU。降级只能减少计算与装饰，不能改变真实身份、锐利核心、会话种子或无跳转原则。

## D-035：Agent 理论概览使用混合恒星 LOD

状态：已接受

Agent 理论论文使用银白锐利亮核与所属热点的中低饱和色相；不再由 CPU 和 Shader 重复白化。概览热点使用正常混合的锐利高温核心，以及同一实体索引上的短衍射和不超过约 12% 透明度的薄日冕；禁止方向光 Lambert 球体、实心蓝色圆片和固定高光。完整光球仅在飞近后的局部热点系统显示。该决定不改变独立理论星图和展示星图。

## D-036：大型开发必须维护开发总账

状态：已接受

`DEVELOPMENT.md` 是大型工作包的权威过程入口。新阶段、重大功能、架构或导航变化、人工验收结论、自动与实机结果不一致、计划替换和关键决定推翻时，必须同步记录计划、实际日志、偏差、证据、进度、遗留问题和提交。`PROJECT / ROADMAP / STATUS / ARCHITECTURE / DECISIONS` 继续各自承担单一职责。
