旧候选保留在 Git 历史和验收材料中，不删除、不继续作为产品候选，也不作为新视觉的截图基准。

## D-005：清晰度优先于粒子数量

语义星必须拥有全分辨率锐利亮核，不参与景深模糊、运动模糊和低分辨率放大。性能不足时先减少装饰粒子和后处理。

## D-006：颜色克制

状态：已接受

默认颜色以银白、冷灰和低饱和灰蓝为主。热点通过尺寸、密度和局部关系表达，只有当前焦点允许短暂增加能量或饱和度。

## D-007：3,840 是常驻预算，不是检索边界

状态：已接受

背景只常驻 3,840 个确定性抽样论文代理。库中其他论文通过只读解析和动态焦点层按需出现。

## D-008：区分快照内未抽样与新信号

状态：已接受

背景快照内未抽样论文直接在所属流带凝聚；只存在于活动数据库或更新快照的论文标记为“新信号”；不存在实体不伪造位置。

## D-009：呼吸不改变语义星核心透明度

状态：已接受

呼吸使用局部密度、空间潮汐和弱光晕变化。语义星中央亮核不得通过时间驱动透明度闪烁。

## D-010：默认首页延后

状态：已接受

参数化引擎、动态聚焦、性能和人工视觉选择完成前，不替换默认首页、不改造对话框和侧栏。

## D-011：引力织场只作为第一套技术骨架

状态：已接受

M1.2a 先实现 `gravitational-weave-tech-preview`，验证固定相机下由知识空间自身产生的拉伸、压缩、剪切、弯曲与恢复。技术审计通过不能把它自动升级为最终主视觉；动态视频人工验收仍是停止门。

## D-012：固定相机作为运动真实性基准

状态：已接受

M1.2a 的主要视觉验收使用固定相机，排除相机环绕、整景旋转和统一平移制造的伪流动。轻微协同漂移只作为补充视差，位移不得超过 `0.6` 世界单位，周期不得短于 60 秒。

## D-013：中央对话区采用缓流而非留空

状态：已接受

未来对话框区域使用固定世界空间缓流椭球，将位移和速度降低约 30%。它不清空中央星体、不形成明显圆洞，也不跟随相机实时移动。

## D-014：M1.2a 保持黑白且无后处理

状态：已接受

第一轮只用银白、冷灰和石墨灰验证运动骨架；语义星采用正常透明混合，不加入 Bloom、景深、运动模糊、拖影或时间透明度。颜色和相位呼吸只有在运动语言被人工接受后才进入下一阶段。

## D-015：引力织场运动语言通过人工判断

状态：已接受

用户确认固定相机与轻微协同漂移的运动效果可以继续使用。视频中的星体轻微软化按录屏压缩处理，不允许因此在渲染器中加入模糊或降低锐利星核分辨率。

## D-016：论文聚焦使用三级触发

状态：已接受

普通提及触发 `signal`，Agent 重点论述触发 `soft-focus`，引用点击或明确聚焦触发 `full-focus`。完整聚焦持续到显式退出或目标切换；柔焦在回答结束约 2 秒后释放。

## D-017：完整聚焦采用中度接近与自适应避让

状态：已接受

完整聚焦约 2 秒进入共速视角，与目标保持约 44 世界单位距离。目标根据原投影侧进入最近安全区域，避开未来居中对话框，不依赖改变 FOV 或移动目标世界坐标。

## D-018：星空不显示论文标题

状态：已接受

聚焦只使用同一论文星的尺寸、亮度、局部关系和相机变化表达。标题与引用信息由未来对话框承担，星空中不生成标签、圆环、准星或霓虹提示。

## D-019：常驻论文使用同一顶点聚焦

状态：已接受

M1.3a 保留全部 3,840 个稳定论文顶点。质量预算隐藏的常驻论文按 ID 提升原顶点，不创建替代对象；目标切换使用双槽交叉过渡，不要求旧目标先返回基础视角。

## D-020：评审背景采用纯黑，焦点采用低饱和语义材质

状态：已接受

引力织场评审背景统一使用 `#000000`。星体必须以紧致亮核和像素级边缘抗锯齿保持清晰，远处只能更小、更暗，不能更模糊。聚焦目标从所属热点颜色确定性派生低饱和材质，并通过连续的尺寸、RGB 能量和局部邻域关系表达；不加入 Bloom、圆环、准星、标题或时间透明度闪烁。具体光学实现由 D-021 的恒星光球 LOD 取代旧晶面方案。

## D-021：语义星统一采用恒星光球 LOD

## D-022：语义色继承热点色相

状态：已接受

热点使用现有热点色的低饱和版本，论文继承同一色相但降低色度，聚焦只连续提高受光层次而不切换色相。年份、排名和数量不生成新色相；颜色只承担辅助语义，不替代尺寸、光球厚度、亮核比例和日冕层级。

## D-023：聚焦先可见，再响应空间，最后移动相机

状态：已接受

完整聚焦的顺序固定为 `FocusTimeline → FocusField → PhotosphereLOD → Camera`：前 0.65 秒完成目标捕获与光球展开，局部潮汐弯曲随后形成，相机约 0.95 秒后才开始接近。释放时相机先回归，目标与局部织场延迟衰减；即使关闭聚焦相机，完整聚焦也必须达到 `8.5 CSS px` 并可独立辨认。

## D-029：背景实体来源必须明确且不可伪造

可点击引用只能指向同一回合中已由搜索返回且已成功读取的真实论文 ID。引用收口失败时保留生成文本，但必须显示核验失败并禁止引用与聚焦；本地无结果时一般知识说明必须与本地证据结论分开。

## D-114：论文数据库内容一律视为不可信数据

状态：已接受并实现

标题、摘要及其他数据库字段只作为证据数据，不能改变系统提示、工具权限或引用规则。原始工具参数、摘要正文和完整问题不写入普通日志；每回合工具次数、单篇摘要和累计结果均设置硬上限。

## D-115：库概况是第四个无参数只读工具

状态：已接受并实现

全库论文数、学科数、热点数和活动快照规模不得由宽泛检索推测。Pi 增加唯一的 `sidera_get_library_overview({})`，工具不接受项目、路径或 SQL，只能读取 Rust 注入项目；每回合最多一次，总工具预算相应调整为七次。

## D-116：正式对话以轮次为根级事实并使用安全 Markdown

状态：已接受并实现

用户问题、检索状态、回答、引用和聚焦属于同一个 `SideraConversationTurn`，不能再分别维护或分组渲染。回答正文使用禁用原始 HTML、图片和危险协议的 GFM Markdown；结构化引用仍只能来自可信 `entityRefs`。

## D-117：证据读取后必须通过结构化完成门

状态：已接受并实现

一旦搜索命中并读取论文，模型的过程旁白和未收口文本不能作为正式证据回答发布。宿主每回合最多一次内部 steer 要求先执行 `finalize_evidence`；失败进入 `invalid`，保留明确错误但不生成引用或聚焦，不允许从读取结果中擅自补造引用。

## D-118：Agent 聚焦锚点必须来自真实界面边界

状态：已接受并实现

产品聚焦不得继续依赖固定 `22% / 78%`、理论 `±0.56`或仅按预设面板宽度估算。对话框、证据卡、标题栏和视口的实际边界共同生成目标侧别、直径、间距和锚点；轮播期间侧别固定，窗口变化只连续重算当前构图。沉浸相机、理论近景和 CSS 光学强调必须消费同一个构图结果。

## D-119：科研星图轨道与论文 Journey 共享空间时间线

状态：连续 Journey 原则保留；全场景投影让位由 D-120 取代（PARTIALLY SUPERSEDED）

右侧热点、论文摘要和论文阅读轨道采用内容分档的真实宽度，并据此计算有效星图区域。论文飞近与返回由 Journey 的同一个连续进度同步驱动轨道、投影、锚点和相机距离；不允许固定 8% 偏移、预先横移、独立 acquisition 或返回末帧再清零锚点。Orbit 只能在最终相机与投影状态原子同步后接回写入权。

## D-120：展示星图的星系中心属于物理画布中心

状态：已接受并实现；产品视觉待验收

科研展示星图在概览、热点详情和论文返回后的空闲状态中，星系几何中心必须投影到物理画布中心；右侧轨道是覆盖层，不得通过 `Camera.setViewOffset()`推动整个星系。轨道真实宽度和 24px 间隔只用于计算论文摘要与阅读的安全锚点，论文 Journey 负责把目标论文连续移动到轨道左侧有效区域中心，并在返回时恢复同一系统姿态。Agent 理论聚焦继续使用真实面板边界生成的独立安全锚点。

## D-121：概览旋转枢轴必须绑定场景规范圆心

状态：已接受并实现；产品视觉待验收

展示与理论星图的概览 Orbit 只能围绕各自场景的规范中心旋转；保存姿态可以继承距离、方位角和仰角，但不能用热点系统或论文近景的瞬态 `center`覆盖概览圆心。相机姿态只允许在 `overview + paper idle` 状态向外发布；运行时重建、Fast Refresh 和模式切换发现保存中心不属于前一概览规范中心时，必须丢弃整组瞬态姿态并恢复目标场景默认概览姿态。热点系统内部仍可临时围绕所选主星旋转。

## D-122：Agent 对话只保留折叠输入态与固定阅读态

状态：已接受并实现；产品视觉待验收

Agent 对话不再提供紧凑、阅读、自定义三套展开布局。无轮次时只显示底部 42px 输入条；首次有效提交必须在 Provider 调用前立即进入唯一固定阅读态，手动收起后的下一次有效提交同样恢复。固定阅读态使用 `clamp(560px, 42vw, 760px)`宽度和 `min(56vh, 580px)`历史区上限；旧布局偏好不读取也不主动删除。输入内容只向上增长至 100px，用户消息不绘制背景强调。全局提示由带唯一 ID 的类型化消息负责：成功与普通信息 3 秒关闭，错误保持至用户关闭或被新提示替换。新对话、历史持久化、联网和缓存不由本决定扩展。

## D-123：UI 历史与 Pi 上下文采用双层持久化

状态：已接受并实现；产品验收待完成

所选论文库下新增独立 `Sidera/conversations-v1.sqlite`保存会话元数据和完整 UI 轮次，`Sidera/pi-sessions/project-<hash>/`保存 Pi 原生 JSONL；不得修改论文库 SQLite Schema。SQLite 历史可在 Pi JSONL 缺失时继续阅读，但非空会话必须标记上下文不可恢复并禁止继续提问，不能通过重放旧问题重建上下文。流式回答按 500ms 检查点保存，终态强制保存；异常退出只标记中断，不自动重放 Provider 请求。

## D-124：历史抽屉与固定阅读面板构成一个几何整体

状态：已接受并实现；产品视觉待验收

R3 的折叠输入态和唯一固定阅读态继续有效。宽屏打开历史时，抽屉、16px 间距和对话框的组合外缘中心必须等于物理屏幕中心：对话框右移 `(drawerWidth + 16px) / 2`，抽屉左移 `(dialogWidth + 16px) / 2`；关闭沿同一 transform 路径返回。小于 960px 时抽屉覆盖，不推动对话框。历史与空间聚焦互斥，避免遮挡和错误锚点。

## D-125：通用能力由 Rust 审计桥提供而不是继承 Pi 内置工具

状态：已接受并实现；真实工具验收待完成

Pi 保留 `--no-builtin-tools`。目录、文件读取/搜索和 HTTPS GET由 Rust 结构化执行；文件写入、编辑、删除与 PowerShell 一律逐次审批。审批必须绑定当前 session、message、工具名、`toolCallId`和参数哈希，批准后立即消费；旧 epoch/revision、迟到响应和不可信工具输出不能批准新操作。Shell 环境必须从空环境重建最小白名单，模型密钥、Token、Cookie、密码和私钥不得继承或进入聊天/事件日志。用户要求不以过度权限限制削弱 Agent，但所有外部副作用仍由明确的人机确认承担。

## D-126：缓存偏好只提供 auto 与显式 long

状态：历史策略；默认 `auto`已被 D-131 取代，错误不降级与统计语义继续有效

默认 `auto`沿用 Pi 与供应商兼容策略，不自行伪造缓存结论；用户显式选择 `long`后，只在新建或重新打开 Pi 进程时注入原生长缓存偏好。上游拒绝参数必须显示持久错误，不静默降级或重发。UI 统计分别展示 input、output、cacheRead、cacheWrite、成本和上下文占用；零缓存值只能表述为“未检测到缓存用量”。

## D-127：对话工作区采用静态 Liquid Glass 材质

状态：静态与无障碍边界继续有效；深色材质参数被 D-130 取代

完整对话框、历史抽屉、标题栏、按钮和输入区共享一套深色玻璃变量，助手长正文使用更稳定的烟熏玻璃。材质只允许静态模糊、半透明层、边缘高光和阴影，不复制 Apple 专有资产，也不增加 WebGL、动态噪声或逐帧滤镜。必须提供 reduced motion、降低透明度、高对比度、forced colors 和不支持 `backdrop-filter`时的纯色退路。

## D-128：会话 Schema 只允许可验证的原始 SQL 与非破坏性补全

状态：已接受并实现；原生产品验收待完成

会话 DDL 必须来自保留换行的独立 SQL 文件，普通语句必须使用不会吞空格的原始多行字符串。`open_store()`只有在 WAL/外键已设置、事务内 v1 Schema 创建完成、列/索引/级联外键验证成功后才能写入 `user_version=1`。`user_version=0`的兼容部分库允许原地幂等补全并保留已有行；版本更高或结构不兼容时必须以安全错误码失败，禁止删除、重建或重放 Provider 请求。

“Provider 连接成功”不得再等价于“Agent 可对话”。设置页必须把 Provider、会话存储和 Pi 运行时分别检测，三项全部通过才给出整体成功。长 SQLite/Pi 技术错误只放在可展开详情中。SQLite 定向测试必须由不链接 Tauri 对话框运行时的 harness 执行；正式桌面继续加载原生 dialog 插件。

## D-129：普通页面导航不拥有 Agent 轮次生命周期

状态：已接受并实现；原生连续性待验收

Agent 的活动轮次、Pi 事件、检查点和工具等待由根级会话控制器持有。切换到文献、热点、科研星图、设置或运行中心只改变可见页面，不得调用 abort、停止 Pi 子进程或创建新轮次。明确停止、项目切换、影响 Pi 的配置保存、新建/切换/归档/删除当前会话及应用退出仍可停止，并沿用确认与终止事件完成门。

Agent 以外页面必须通过标题栏显示正在回答或等待审批。审批不能在上下文之外直接批准，用户必须返回原 Agent 审批卡；完成提示 3 秒结束，后台错误使用持久全局错误提示。导航连续性不得以自动重放 Provider 请求实现。

## D-130：清透光学外壳与连续烟熏阅读层取代深色嵌套玻璃

状态：已接受并实现；产品视觉待验收

D-127 的静态 CSS、无逐帧滤镜和无障碍降级继续有效，但深色高遮蔽参数与逐回答烟熏卡片被取代。对话框、历史抽屉、折叠输入和标题栏状态共享 18px模糊、115%饱和度和约 34%深色外壳；全部对话历史位于约 58%的单一烟熏阅读层，助手回答自身不再绘制背景、硬边或卡片阴影。

镜面强调只允许窄顶部/左侧边缘和短局部高光，不得恢复左上大片径向灰雾。历史抽屉列表默认透明，输入区为内嵌玻璃槽；在降低透明度、高对比度、forced colors 或无 `backdrop-filter`环境继续使用可读纯色退路。

## D-131：长缓存成为默认策略并以版本标记完成一次性迁移

状态：已接受并实现；真实 Provider缓存待验收

新项目、缺失字段和旧格式备份默认使用 `long`。设置内部使用缓存策略 v2 标记；启动时所有未标记的 `auto`、`long`或缺失值一次性迁移为 `long`并补标记。带 v2 标记后，用户显式选择的兼容模式 `auto`必须在保存、重启和新版备份恢复后保持，不得再次迁移。

`long`仍只在新建或重新打开 Pi 会话时生效。上游明确拒绝长缓存参数时必须返回持久安全错误并引导用户手动切换兼容模式，禁止静默降级、自动重试或重放付费请求。是否真实命中缓存只能由 UI 统计与上游记录验证，首次写入为零不构成失败结论。

## D-132：流式正文由 Pi 事件类型控制，不使用字节阈值猜测

状态：已接受并实现；真实 Provider首段流式待验收

普通文本的首个 `text_delta`必须立即进入前端，不再等待固定字节数。`toolcall_start`进入显示隐藏态，并在已有可见前言时发送 `assistant-replace`精确清空；系统工具完成后立即释放下一段最终回答，RAG 则继续等待概况、无结果或证据 `finalize`完成门。再次出现工具调用时可再次撤回该阶段尚未核验的前言。

显示状态与工具安全状态彼此独立：`toolcall_start`不能授权执行，既有 `tool_execution_start`白名单、审批绑定和迟到响应隔离继续负责安全。用户停止普通回答时保留已显示部分；隐藏旁白不得在停止或结算时补出；证据失败使用替换事件，不能把固定失败说明追加在未核验正文之后。

## D-036：大型开发必须维护开发总账

状态：已接受

`DEVELOPMENT.md` 是大型工作包的权威过程入口。新阶段、重大功能、架构或导航变化、人工验收结论、自动与实机结果不一致、计划替换和关键决定推翻时，必须同步记录计划、实际日志、偏差、证据、进度、遗留问题和提交。`PROJECT / ROADMAP / STATUS / ARCHITECTURE / DECISIONS` 继续各自承担单一职责。
