## 1. 文档地位

本文详细定义本项目的最终产品形态、用户体验、能力边界和完成标准。范围、当前阶段和优先级以 `PROJECT.md`、`ROADMAP.md`、`STATUS.md`、`ARCHITECTURE.md` 和 `DECISIONS.md` 为事实入口；本文作为产品细节来源。

下列文档继续有效，但其地位调整为基础设施或历史版本说明：

- `V20_FINAL_HANDOFF.md`：本地论文库、热点建模、星图和终局验收基础设施。
- `agent-v0.22-contract.md`：第一代受监督 Agent 的执行、安全和持久化契约。
- `deferred-development-roadmap.md`：未进入当前主路线的实验方向和远期扩展。

V20、理论星图、报告审计和现有 Agent 运行系统不是最终产品本身，而是最终科研 Agent 的证据、工具、安全和空间表达基础。

## 2. 产品北极星

最终产品是一个面向个人科研人员、研究生和教师的 Windows 桌面科研 Agent：

> 用户打开程序后，首先进入一个全屏沉浸式星空中的极简 Agent 对话空间。Agent 以本地论文库、热点、理论星图和可追溯证据为核心知识基础，可以按需调用受控在线学术检索，并在用户批准后执行导入、清洗、建模、报告生成和正式导出。传统功能页退居为可由 Agent 调用、也可由用户主动进入的专业工作空间。

产品必须同时成立三件事：

1. 第一眼是有辨识度、有冲击力的沉浸式科研空间，而不是传统管理后台。
2. 核心交互是自然语言对话，而不是要求用户先理解流水线和数据结构。
3. 每一个科研结论都能回到真实论文、热点、快照和来源，视觉效果不能取代证据真实性。

## 3. 目标用户与核心任务

### 3.1 目标用户

第一目标用户是单机工作的个人科研人员、研究生和教师。第一阶段不引入多人账号、组织权限、云同步或协作编辑。

### 3.2 核心任务

用户应当能够通过对话完成或发起：

- 查询本地论文库中的某篇论文、某组论文或某个热点。
- 对比论文、方法、研究方向、年份演化和来源差异。
- 通过可点击引用定位原始论文、热点或星图位置。
- 在本地证据不足时，调用受控在线学术搜索或受控通用网页搜索。
- 将选定在线结果在用户确认后导入本地论文库。
- 发起清洗、去重、Embedding、聚类和热点建模。
- 观察真实建模过程，理解论文如何凝聚成热点和理论星图。
- 基于选定证据生成、修订、审计和导出研究报告。
- 随时打开治理详情，查看计划、工具调用、审批、预算、事件和 Artifact。

## 4. 应用信息架构

### 4.1 默认入口

正常启动时无条件进入 Agent 首页，不再默认进入项目 Dashboard。

即使尚未满足下列条件，也仍停留在 Agent 首页：

- 没有导入论文。
- 没有活动 V20 快照。
- 没有配置对话模型 API。
- 当前数据库需要迁移或恢复。

此时对话区域显示明确的空状态和下一步，不自动导入、清洗、聚类或联网。

### 4.2 默认隐藏导航

每次程序启动时，主功能边栏默认关闭，不记忆上次打开状态。

右上角保留一个低干扰、半透明、小尺寸的导航按钮。点击后，边栏以覆盖层形式滑入，不挤压星空背景和对话区。

边栏一级入口为：

- 项目总览
- 文献与建模
- 科研星图
- 热点库
- 报告库
- Agent 运行详情
- 任务日志
- 设置与健康检查

### 4.3 文献与建模

原“文献工作台”和“分析流水线”合并为同一个用户入口“文献与建模”，但代码和数据层继续保持模块化。

内部子空间包括：

- 文献检索
- 本地论文库
- 阅读与详情
- 导入记录
- 清洗与去重
- Embedding 与缓存
- 星系诞生观测站
- 任务、暂停、失败和恢复

Agent 可以通过深链接将用户带到其中的具体子空间。

## 5. Agent 首页体验

### 5.1 初始形态

首页由全屏星空背景和居中的极简对话框组成。

初始对话框只包含：

- 一行或多行自适应输入区。
- 发送/停止按钮。
- 当前证据范围提示，例如“本地库”“允许联网”。
- 必要时显示模型、项目或快照未就绪状态。

对话框采用半透明材质，不占据大面积屏幕，不使用传统后台卡片墙。

### 5.2 对话展开

发送第一条消息后：

- 输入框向中央偏下位置移动。
- 最近对话在其上方渐进展开。
- 长回答可继续展开为完整会话视图。
- 用户可将会话收回为极简模式。
- 星空仍然是空间主体，但回答期间自动降低运动和亮度。

### 5.3 会话持久化

会话按项目保存在 SQLite 中，并支持：

- 多会话。
- 重命名。
- 归档。
- 删除。
- 恢复流式中断前的已提交内容。
- 消息、引用、工具摘要、审批结果和最终 Artifact 的关联。

不得保存模型思维链。只保存用户可见内容、简洁决策摘要、结构化证据、工具结果和审计事件。

## 6. Agent 星空背景

### 6.1 数据来源

Agent 背景基于一个明确记录的理论星图快照生成。默认使用用户已确认的稳定背景快照，而不是每次启动自动切换到最新活动快照。

当检测到新的活动快照时：

- 不静默替换背景。
- 提示用户存在新星图。
- 展示变更摘要。
- 由用户决定是否更新背景快照。

背景必须记录：

- 数据库身份。
- 项目 ID。
- 来源快照 ID。
- 布局版本。
- 生成时间。
- 视觉配置版本。

### 6.2 真实性与视觉自由

背景应保留：

- 热点宏观方向。
- 学科色系。
- 主要相对关系。
- 可追溯的论文和热点身份。

背景允许为了沉浸感进行大胆的展示性加工：

- 确定性抽样论文星。
- 多层星尘。
- 视差。
- 星流和能量丝。
- 景深。
- 克制但有冲击力的 Bloom。
- 缓慢相机漂移。
- 局部脉冲。
- 穿越感和空间层次。
- 对话、引用和工具状态触发的视觉响应。

这些加工不得改变科研分析结果，也不得声称展示坐标是严格理论坐标。界面应将其定义为“基于理论星图的沉浸式表达”。

### 6.3 运动状态

背景至少有四种运动状态：

1. 空闲：流动性和视觉冲击最强。
2. 用户输入：降低位移和亮度，保留轻微呼吸。
3. Agent 流式回答：进一步降低运动，突出引用与目标星体。
4. 长文阅读：进入低干扰模式，只保留深空视差和微弱呼吸。

窗口失焦、不可见或系统启用减少动态时，应暂停或显著降级。

### 6.4 性能目标

最低验收设备为 Intel Iris Xe、16 GB 内存、1080p：

- 空闲背景稳定不低于 30 FPS。
- Agent 流式回答时不低于 24 FPS。
- 不阻塞输入、流式文本、引用点击和停止生成。
- P95 帧耗时连续超限时自动降低粒子数、Bloom、景深和更新频率。

RTX 4060 等独立显卡可以启用更高粒子密度、更多层视差和更强后处理，但不能形成两套不同的信息语义。

## 7. 对话驱动的空间聚焦

空间聚焦是最终产品的标志性能力。Agent 返回结构化实体身份和视觉焦点意图，背景据此响应，不依靠对回答文本做不稳定的二次猜测。

### 7.1 单实体

用户明确询问一篇论文或一个热点时，背景自动聚焦。

推荐节奏：

1. `0–180 ms`：回答区实体名称或引用点亮。
2. `180–900 ms`：星空产生方向性视差，相机沿真实语义方向接近。
3. `900–1500 ms`：目标成为画面中央偏上约 38% 的视觉中心。
4. `1500–1900 ms`：邻域、论文云或热点语境柔和显现。
5. 回答开始后，背景转入低干扰阅读状态。

热点聚焦到热点系统附近。论文采用两段式聚焦：

```text
全局星图
  → 论文所属热点
  → 目标论文星
```

### 7.2 多实体

一次查询涉及多个论文或热点时：

- 不自动依次飞行。
- 在当前视图中同时点亮。
- 使用临时空间连接和编号对应回答引用。
- 用户点击引用后再聚焦单个实体。

### 7.3 顺带提及

回答只是顺带提到某实体时，仅让对应星体短暂呼吸，不移动相机。

### 7.4 新信号

如果实体存在于活动数据库或新快照，但不在固定背景快照中：

- 不伪造其在旧快照中的位置。
- 以“新信号”从星空边缘进入。
- 标明其尚未属于当前背景快照。
- 允许在当前会话中临时显示。
- 提供更新背景快照的明确操作。

## 8. 本地检索与证据

### 8.1 第一阶段索引范围

第一阶段索引：

- 标题
- 摘要
- 作者
- 关键词/分类
- 来源
- 年份
- 学科
- DOI
- 热点归属

PDF 全文、OCR 和分段检索属于后续阶段。第一阶段必须预留文档片段和页码引用结构，但不因全文能力延迟基本产品。

### 8.2 混合检索

本地检索采用：

- SQLite FTS5/BM25 词法召回。
- 本地 E5 Embedding 语义召回。
- 年份、来源、学科、热点和项目等结构化过滤。
- 词法与语义结果混合重排。
- 证据去重和来源多样性控制。

当前 `search_blob LIKE '%term%'` 只能作为迁移期间兼容路径，不能作为最终大库检索实现。

中文检索必须经过独立验收。优先评估 FTS5 trigram；如果打包 SQLite 不支持或效果不足，则使用应用层稳定 n-gram/分词索引。

### 8.3 语义索引

本地 E5 模型继续用于 Embedding、语义检索、聚类和星图，不承担对话生成。

语义召回应绑定：

- 模型 ID 和精确 revision。
- 向量维度。
- 内容哈希。
- 数据库修订。
- 索引版本。

在 100K 规模上根据基准测试选择持久化近邻索引或候选集内精确余弦检索。不得在没有性能证据时固定某个第三方向量扩展。

### 8.4 引用要求

只要回答涉及论文事实，就必须给出可点击引用。

引用至少包含：

- 论文 ID。
- 标题。
- 来源。
- 年份。
- 本地/在线标记。
- 支撑回答的摘要片段或证据片段。
- 所属热点和来源快照（适用时）。

证据不足时，Agent 必须说明不确定性或继续检索，不得补写不存在的论文事实。

## 9. 联网检索

### 9.1 范围

第一阶段采用“学术 API 优先，必要时受控通用网页搜索”：

- OpenAlex
- arXiv
- Crossref
- PubMed
- 后续经独立授权接入的机构或学校图书馆来源

受控通用网页搜索通过明确的搜索提供商和只读页面提取器完成，不提供任意浏览器控制、登录绕过、Cookie 导出或访问控制规避。

### 9.2 临时证据与入库

联网结果默认只属于当前会话的临时证据：

- 必须标记在线来源。
- 记录查询、时间、来源 URL、许可和 provenance。
- 可以参与当前回答。
- 不自动成为本地论文库记录。

Agent 可以建议入库，但必须由用户批准。入库后执行规范化、DOI/标题/内容去重和来源记录。

### 9.3 机构来源

学校图书馆或商业数据库必须通过独立连接器接入：

- 优先正式 API、OAI-PMH、Z39.50 或供应商授权接口。
- 凭据保存在 Windows Credential Manager。
- 按项目和服务商隔离。
- 不依赖导出浏览器 Cookie。
- 不绕过验证码、付费墙、IP 或机构访问控制。

## 10. 对话模型供应商

产品不内置、不下载、不要求运行本地对话大模型。

本地 E5 Embedding 模型继续保留；对话和规划由用户配置的模型 API 提供。

统一模型层至少支持：

- OpenAI Chat Completions 兼容协议。
- OpenAI Responses 兼容协议。
- Anthropic Messages 兼容协议。
- 自定义 Base URL。
- 自定义模型名称。
- 流式输出。
- 取消和超时。
- 结构化响应能力探测。
- Token 统计。
- 可选费用估算。

DeepSeek、OpenAI、Anthropic 及兼容供应商通过上述适配器接入。Gemini、Azure OpenAI 等特殊协议通过可扩展 Provider Adapter 增加。

不提供可以任意拼接请求、任意设置敏感头或执行任意脚本的“万能 HTTP 模板”。

API Key 和凭据必须保存在 Windows Credential Manager 或明确允许的开发环境变量中，不进入：

- 会话正文
- 模型上下文
- 计划
- 工具输入
- 事件
- Artifact
- 日志
- 备份

## 11. Agent 权限与治理

默认采用受监督模式：

- 本地只读检索、热点读取和论文证据读取可以在已批准计划内自动执行。
- 受控在线只读检索可以执行，并在界面中显示联网状态。
- 入库、清洗、聚类、数据库修改、正式报告导出必须确认。
- 删除、覆盖和不可逆动作始终单独确认。
- 不增加完全自主模式。

用户可以通过自然语言请求其他功能，但自然语言不能绕过动作风险：

- “导入这些论文”
- “重新运行热点建模”
- “生成这个热点的报告”
- “打开这篇论文所在的星系”

现有计划、步骤、审批、预算、租约、事件、Artifact 和报告复核继续由后端权威状态机管理。当前 Agent 工作台转为“Agent 运行详情”专业页面，而不是默认首页。

## 12. 星系诞生观测站

### 12.1 产品目标

聚类页面不再只是进度条。它应显示论文如何从混沌星尘逐渐形成热点，并最终生长为正式理论星图。

### 12.2 真实性原则

- 只展示已经计算出的状态。
- 不按时间比例伪造热点数量。
- 后端没有部分结果时，只展示真实阶段、吞吐、缓存和混沌星尘。
- 结果完成后可以提供明确标记的“构建回放”，不能冒充实时计算。
- 临时预览不能写入或替换活动 V20 快照。

### 12.3 稳定粒子身份

每篇论文从开始到结束都是同一颗粒子：

- 论文 ID 决定稳定粒子身份和初始混沌种子。
- Embedding 完成后，同一粒子获得语义方向。
- 归属变化时沿连续、至少 C1 连续的轨迹移动。
- 不删除旧对象再创建新对象。
- 不因排序变化更换几何槽位。
- 不发生前十论文曾出现过的排队、瞬移或对象替换。

### 12.4 真实阶段

1. 黑暗期：读取数据库、检查缓存和准备资源。
2. 星尘苏醒：完成 Embedding 的论文批次逐渐点亮。
3. 混沌流动：语义相近粒子形成真实流场。
4. 原恒星核心：后端产生临时聚类后出现密度核心。
5. 引力凝聚：论文粒子向实际热点区域连续靠拢。
6. 星系重组：临时热点真实合并、分裂、变暗或重命名。
7. 语义定形：质心和三维投影完成，星系向理论坐标收敛。
8. 原子提交：提交成功后无缝成为正式理论星图。

临时热点可以合并、分裂或消失，必须标记为“临时结果”并采用连续视觉交接。

### 12.5 交互

建模期间允许：

- 旋转和缩放。
- 暂停观察。
- 悬停查看真实阶段、论文数、稳定度和缓存状态。
- 离开页面后任务继续。
- 返回后恢复当前真实状态。

提交完成前，不允许把临时热点用于正式报告、证据链或论文详情跳转。

## 13. 规模目标

100,000 篇论文继续作为性能、稳定性和最终验收规模，但不是用户开始使用产品的前置条件。

程序在小型和中型论文库中也必须提供完整功能。

100K 验收至少覆盖：

- 导入、恢复和去重。
- FTS5 索引构建与增量更新。
- 混合检索延迟。
- Embedding 缓存复用。
- 建模进度和预览事件吞吐。
- Agent 多轮检索。
- 星图载荷与渲染。
- 报告证据链。

## 14. 非目标与延后项

第一阶段不包含：

- 多人账号和实时协作。
- 云端项目同步。
- 完全自主 Agent。
- 任意网页浏览。
- 任意 SQL、Shell 或文件系统工具。
- 自动绕过机构授权。
- 自动批量导入在线结果。
- 内置本地对话大模型。

## 15. 最终验收标准

### 15.1 首屏

- 正常启动直接进入 Agent 首页。
- 边栏默认关闭。
- 无数据库、无快照或无模型时仍可理解下一步。
- 输入焦点和首帧星空在可接受时间内就绪。

### 15.2 视觉

- 背景可追溯到固定理论快照。
- 空闲、输入、回答和阅读四种运动状态可区分。
- 单实体、多实体和新信号聚焦行为正确。
- 不出现对象瞬移、重排、闪白或突然生成。
- 减少动态和低性能降级可用。

### 15.3 检索

- 25K 和 100K 规模均完成性能验收。
- 中文和英文查询都有可用召回。
- 词法、语义和结构化过滤可组合。
- 回答引用能回到真实论文和证据片段。

### 15.4 Agent

- 支持持久化多会话、流式输出、停止和恢复。
- 可以通过自然语言调用本地检索、热点、星图和报告能力。
- 写入和高风险动作不能绕过审批。
- 无证据时明确说明，不生成虚假引用。

### 15.5 联网

- 学术 API 和受控通用搜索均有 provenance。
- 在线结果与本地论文明确区分。
- 未经批准不入库。
- 机构来源不绕过授权边界。

### 15.6 建模

- 预览来自真实计算事件。
- 粒子身份稳定。
- 临时热点合并、分裂和退出连续。
- 最终无缝生成理论星图。
- 取消、失败、暂停和恢复不会污染活动快照。

### 15.7 原生交付

- Windows Tauri 原生流程通过。
- 安装、升级、重装和卸载通过。
- 外部数据库和凭据不被误删。
- Full/Lite 或后续分发形态与当前产品能力一致。

## 16. 完成定义

只有当以下陈述全部为真，才能宣布最终产品目标完成：

1. Agent 星空首页是正常启动入口。
2. 用户可以仅通过对话完成本地检索、证据定位、联网补充、建模发起和报告生成。
3. 每个科研事实都能追溯到本地或在线证据。
4. 星空能响应论文、热点、快照和Agent状态，而不是无关装饰动画。
5. 星系诞生观测站展示真实建模过程并最终生成理论星图。
6. 所有写入和高风险动作仍受审批、事务和审计约束。
7. 25K 与 100K 规模、集显与独显、原生 Windows 交付均通过验收。
